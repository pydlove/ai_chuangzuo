# 约稿中心视觉与响应式设计规格

## 目标

重做用户端约稿中心的展示层，优先改善电脑端任务大厅的信息层级与设计感，再针对手机端优化单列浏览和投稿操作。业务模型保持不变：约稿任务只能由管理端管理员发布，用户只能浏览任务并投递爱创作中已经生成完成的文章。

## 业务边界

- 用户端不提供发布、编辑或删除约稿任务的入口。
- 任务来源统一展示为平台官方/管理员发布。
- 用户只能从自己已生成完成且字数符合要求的文章中选择投稿。
- 管理员采纳后，奖励全额发放给用户。
- 不新增接口，不改变现有任务、投稿、撤回和奖励状态规则。

## 视觉方向

采用“任务大厅 + 奖励导向卡片”方案：

- 保留现有品牌红 `#ff2442` 与设计系统 CSS 变量。
- 页面头部使用淡红、淡紫浅渐变，形成官方任务大厅的视觉识别。
- 任务卡片以奖励、任务标题、截止时间和采纳名额为核心信息。
- 招募中、待采纳、已完成、已流局使用蓝、橙、绿、灰四类状态色。
- 不新增图片资源或第三方 UI 组件。

## 电脑端约稿大厅

### 顶部概览

展示“官方约稿任务”标题、说明和真实统计：进行中的任务、我的投稿、已获得创作币。说明文案明确“管理员发布任务”和“采纳后全额奖励”。概览区使用轻渐变背景和抽象 CSS 装饰。

### 导航与筛选

保留“全部任务”和“我投稿的”两个视图，改为胶囊式分段控件。全部任务视图提供全部、正在招募、待采纳、已完成、已流局筛选；已流局视觉降级但不改变接口返回逻辑。

### 全部任务卡片

电脑端使用双列卡片布局。每张卡片展示状态、奖励、标题、两行以内描述、字数范围、计划采纳数量、已采纳数量、截止时间和详情入口。整张卡片可点击，招募中任务 hover 时轻微上移并增强阴影。

### 我的投稿卡片

我的投稿视图使用不同的信息层级，突出投稿文章标题、文章字数、投稿状态、投稿时间和奖励结果。等待采纳、已采纳、未采纳、已撤回分别使用蓝、绿、灰、浅灰状态表达。页面不出现任务发布类操作。

## 电脑端详情页

采用左侧任务内容、右侧固定操作卡布局：

- 左侧展示返回入口、任务状态、标题、任务说明、字数要求和风格提示。
- 右侧突出奖励金额、计划采纳数量、截止时间、全额发放说明和投稿操作。
- 招募中且未投稿显示“选择文章投稿”。
- 已投稿显示文章和投稿状态。
- 已采纳显示“奖励已发放至你的创作币账户”。
- 已截止、已完成、已流局隐藏或禁用投稿操作。
- 文章选择弹框展示标题、字数、平台和生成完成时间；不符合字数范围的文章禁用并说明原因。

## 手机端

手机端使用已有移动子页面导航，不重复显示桌面侧栏。

### 手机大厅

头部压缩为“官方约稿”和简短说明，统计改为可横向滚动的小指标卡。任务采用单列卡片，奖励固定右上角，描述最多两行，元信息允许换行，避免过小字号和拥挤按钮。

### 手机详情

内容按状态、标题、奖励、截止/字数/采纳指标、任务说明、风格提示、投稿说明垂直排列。招募中且未投稿时使用底部固定操作栏，操作按钮保持拇指可达；已投稿、已采纳、已截止状态分别替换为状态提示，不展示无效操作。

## 响应式规则

- 电脑端宽屏使用双列任务卡，窄桌面自动降为单列。
- 手机端断点沿用项目已有 `768px` 规则。
- 手机端卡片内边距 16px，桌面端卡片内边距 20-24px。
- 操作按钮最小触控高度 40px。
- 弹框内容内部滚动，避免页面高度随文章列表跳动。
- 支持现有明暗主题，卡片、概览区、筛选控件和固定操作栏都提供暗色背景适配。

## 验证标准

- 电脑端能清楚区分管理员发布的任务和用户投稿状态。
- 用户端页面不存在发布任务入口。
- 全部任务、我的投稿、详情和投稿弹框均使用真实后端数据。
- 电脑端优先验证任务浏览、详情和投稿黄金路径。
- 手机端验证单列卡片、详情滚动、固定投稿栏和投稿状态展示。
- 构建通过，且不影响现有登录、作品列表和 Console 导航。
